## 1. Protocols (non-negotiable)

**Silicon protocol:** (1) final ELF must change for the intended generic mechanism; (2) OFF/ON identical source/input/golden, only compiler flags differ; (3) paired CRAQ correctness first; (4) independent review of compiler mutations before silicon; (5) serialize ALL device jobs under two exclusive flocks — `flock -x /tmp/tt-device.lock -c "flock -x /tmp/tt-llk-sfpu-silicon.lock -c '<one job>'"` (create the files if absent; release = process exit; never parse results while holding); (6) paired physical correctness PASS, then 3 fresh profiler processes per selector, alternating OFF/ON, unique RUNNER_TEMP per process, raw/post CSVs copied before releasing the lock; (7) archive ELF, .text hash, build.h, logs, compiler sha256, SHA256SUMS manifest. CRAQ = correctness/structure evidence only, NEVER a silicon perf oracle. Don't run hardware on byte-identical OFF/ON pairs except as intentional control. Never force-push; normal pushes only. If a distinct handwritten source exists and its OFF/ON .text is byte-identical, one physical hand run fills both hand cells (record the identity).

**Metric caveat (silicon-learned):** the SDPA BODY profiler marker is INVALID for fire-and-forget replay-launch shapes (a measured 367 violated the 512-slot issue lower bound). For such shapes use the drain-inclusive KERNEL marker, or add a math-drain barrier to the marker zone (open harness follow-up). Sanity-check every reading against the payload's issue-slot lower bound.

**Delivery-cost model:** RISC-pushed op ≈ 1.23× a replayed slot (re-fit from measured actuals; the older 2.2:1 over-predicts launch-conversion gains ~7x).
